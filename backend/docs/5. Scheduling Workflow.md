# 6. Validation Layer

Validate everything before touching the database.

Checks include:

```
✓ senderId exists

✓ recipient list not empty

✓ subject present

✓ body present

✓ future scheduled time

✓ valid email addresses

✓ hourly limit > 0

✓ delay >= minimum
```

If validation fails

```
400 Bad Request
```

Nothing is stored.

---

The first operation is always

# 42. Key Design Decisions

| Decision                              | Reason                                     |
| ------------------------------------- | ------------------------------------------ |
| One database row per recipient        | Independent tracking, retries, and status  |
| One BullMQ job per email              | Fine-grained scheduling and recovery       |
| Job contains only `emailId`           | Keeps Redis lightweight                    |
| PostgreSQL is the source of truth     | Reliable dashboard and recovery            |
| Redis stores queue state only         | Fast coordination and scheduling           |
| Worker reloads from DB                | Supports cancellation and idempotency      |
| `jobId = emailId`                     | Prevents duplicate jobs                    |
| Update status before/after processing | Accurate visibility in dashboard           |
| Atomic Redis counters                 | Safe rate limiting across multiple workers |

# 43. Responsibilities Throughout the Flow

| Component          | Responsibility                      |
| ------------------ | ----------------------------------- |
| Frontend           | Collect input, upload CSV, call API |
| Express Route      | Route HTTP request                  |
| Validator          | Validate request payload            |
| Controller         | Delegate to service                 |
| EmailService       | Business logic, persistence         |
| Repository         | Database operations                 |
| QueueService       | Create BullMQ jobs                  |
| Redis              | Store delayed jobs and counters     |
| BullMQ             | Schedule, retry, distribute jobs    |
| Worker             | Execute jobs                        |
| RateLimiterService | Enforce hourly limits               |
| SMTPService        | Send email                          |
| PostgreSQL         | Persist business state              |
| Dashboard          | Display current state from DB       |
